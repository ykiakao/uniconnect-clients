## 5. Limitações da demonstração

- Chat, notificações, lembretes, submissão de trabalhos, publicação de atividades e lançamento docente de notas não estão integrados. Não demonstrar esses protótipos como operações reais.
- A API atual devolve nota por atividade. O adaptador legado ainda mantém seus campos de P1/P2/trabalho internamente, mas a interface apresenta somente a nota recebida; a média simples de consulta não é CR oficial nem critério de aprovação.
- Nota ausente/inválida gera erro recuperável, em vez de virar zero. Prazo ausente não recebe valor fictício.
- Dados acadêmicos opcionais do perfil podem não vir da API. A instituição fallback legada do serviço de autenticação não é apresentada como instituição confirmada quando o ID estiver ausente.
- O frontend não implementa renovação automática de token; esse comportamento anterior foi preservado. Se a sessão expirar, entrar novamente.
- A consulta do aluno percorre cursos → turmas → atividades, como já fazia; depende da disponibilidade e latência da API publicada. Não houve otimização ou mudança de contratos nesta etapa.
- O ensaio automatizado de navegação usa o router real com respostas controladas apenas dentro dos testes. O smoke HTTP exercitou o serviço publicado. Não houve ensaio manual completo em celular físico nem inspeção manual de navegador autenticado.
- QA de layout: seis larguras, texto 1.5x em 375 px e erro em landscape 640×360. Não representa certificação de todos os dispositivos ou estados de teclado.
- Nenhum acesso direto ao Supabase remoto, nenhuma alteração na API, migration, credencial ou dependência. Não se exige aplicar migrations novas para estas mudanças.
